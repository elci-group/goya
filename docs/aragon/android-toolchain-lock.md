# Aragon Android toolchain lock (Phase 2)

Recorded 17 November 2026. This is the single toolchain that
`aragon-android-project` targets and that
`scripts/check-android-apk-build.sh` requires. The script refuses to run
(exit 2) when any locked item differs. It does not install anything.

The generated `gradle.properties` sets `android.builder.sdkDownload=false`,
so AGP fails instead of installing an SDK package outside the lock. The
generated app module sets `compileSdk = 35`, `targetSdk = 35`, `minSdk = 23`,
Java/Kotlin JVM target 17, and has no library dependencies.

## Dependency verification

`gradle/verification-metadata.xml` (copied verbatim from
`crates/goya-sdk/android-template/`) lists SHA-256 checksums for all 246
plugin and build-classpath components resolved by `assembleRelease`, with
metadata verification on. The qualification script runs Gradle with
`--dependency-verification strict`, so an artifact that is missing from the
file or does not match fails the build.

These checksums were **generated by Gradle** (trust on first use) from
`google()` and Maven Central over HTTPS on 17 November 2026. They were not
cross-checked against signatures (`verify-signatures` is off) or an
independent mirror. They detect later substitution, not a compromise that
already existed at generation time.

## Installing the lock on another host

There is no installer. Install the JDK and the SDK packages above under any
prefix, accept the Android SDK licence with `sdkmanager --licenses`, and set
`JAVA_HOME` and `ANDROID_HOME`. On this host they are
`~/.local/opt/jdk-21.0.13+9` and `~/.local/opt/android-sdk`, off the default
`PATH`. The Gradle 8.9 distribution and the verified dependencies are fetched
on first use: run the script once with `--allow-network` (verification still
applies), then offline.

## Reproducibility check

```sh
JAVA_HOME=~/.local/opt/jdk-21.0.13+9 ANDROID_HOME=~/.local/opt/android-sdk \
    bash scripts/check-android-apk-build.sh
```

The script generates the static-text, root-button and compiled-scene
qualification projects,
builds each one twice into an unsigned release APK (`assembleRelease`) from
fresh copies at different paths, offline, with strict verification, and
requires both builds to be byte-identical to each other and to the SHA-256
recorded in the script.

Result on this host, 26 November 2026 (Linux x86-64), branch
`aragon/live-on-lantern`:

Locked-toolchain release APK builds are reproducible and match the recorded hashes.

Re-recorded 26 November 2026. The 17/18 November hashes were
`cd3e6f15…` (static), `47af8d6c…` (root-button) and `c792e345…` (scene).
The static project's generated sources are byte-identical between Lantern
(`b408ee19`) and the GSSH/4-live port, so its drift comes from emitter
changes that landed between 17 November and `b408ee19`. Root-button and
scene additionally change because the port emits one dispatch function
per D1 action (`actionN(inputs)`) instead of inlining each action in the
`when` arm; behaviour is unchanged. Both builds of every project were
byte-identical before and after re-recording.

Exit 0, offline with strict verification. Each hash is the same across both
builds of that project. The root-button hash also equals an earlier
prototype build of the same project on 17 November 2026. The scene project
was added in Phase 3; adding it left the two earlier hashes unchanged. Its
hash changed in Phase 4 (insets, theme and scroll accessibility; rerun 18
November 2026). Kotlin's compile daemon can print a start-up error and fall
back to compiling in-process; the APKs are unaffected.

## What this does not establish

* No APK has been installed or run: emulator and device gates (ARG-G05,
  ARG-G06) are untouched.
* The APKs are unsigned release builds. Signing, bundles and update testing
  belong to ARG-G10.
* Reproducibility is shown on one host and one OS. A second host or a
  different `GRADLE_USER_HOME` has not been tested.
* Only the three qualification scenes are built. Any change to the emitters
  changes the APK hash; the recorded hashes are then updated in the same
  change, with the reason.

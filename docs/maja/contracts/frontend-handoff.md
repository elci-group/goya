# Maja frontend handoff, revision 0

Decision: the only initial source admission entry is `goya_lang::handoff::admit`, returning the immutable in-process GSSH/1 snapshot. This is an integration contract for investigation and skeleton work, not a modification or ratification of GSSH as a public Goya contract. Reject unknown handoff versions. Preserve the original UTF-8 bytes, `ParsedScene` and all source entries as a single revision-bound unit through admission; verify SHA-256 and entry digest consistency. Do not reconstruct semantics from GY-IR alone. Do not treat derived GY-IR node or action numbers as authored identity.

The scene and interaction declarations retain hierarchy, authored IDs, geometry, presentation properties and expressions. `SourceEntry` provides end-exclusive UTF-8 byte ranges, optional authored semantic ID and a within-revision scene path. Scene paths are not stable IDs. An implicit ontology root can lack an authored ID; validate explicit identity according to the canonical frontend rather than inventing stricter rules. Interaction-to-button bindings already exist and must use the canonical compiler's ambiguity and action-ID rules. Source entries are incomplete: attribute errors to the most precise available enclosing origin, explicitly mark absent or fallback origins, and never fabricate expression-level ranges. Features needing unavailable origins remain rejected until the frontend contract supports them.

Strict admission is necessary but not sufficient: every reachable retained field and declaration must have a target disposition. Unknown properties, duplicate properties, unsupported syntax and invalid interaction declarations retain canonical errors; target rejections use separate structured codes and available origins. No fallback is automatic. Failed admission produces no application artifacts.

The authored source does not currently define the complete initial state, input-control-to-action-input mapping or state-to-visible-view binding required by the counter. The SDK's explicit typed caller state is an execution input, not authored UI semantics. A versioned external configuration could be proposed as a separately hashed build input with explicit IDs, complete typed values, bindings, coverage and deterministic validation, but would not alone satisfy the single-authored-application mandate. No such configuration is admitted as an implicit fallback. A shared language/SDK change requires an integration-owned contract-change proposal and approval before implementation.

For D1, compare against the canonical executor: exact i64 checked arithmetic, checked revisions, atomic commit and rollback, typed state and declared keys, and limits including UTF-8 byte lengths. The VM currently bounds text to 64 KiB, snapshots and registers to 1 MiB, contract keys to 256 and instructions to 4096. Derive exact limits and error precedence from the pinned canonical implementation; JavaScript UTF-16 string length and floating-point integers are not equivalent. The private D1 bytecode is not an available public export contract.

# Platform-native differences

None of this is a Windows launch. The Wayland host is not a compiler for the counter scene. `parity-counter` runs the admitted add headlessly and does not open that host. `docs/parity/programme.md` records that Sash admits Enter, Tab, and the copy/paste policy in generated code that has not been launched, and that `goya-wayland` remains a live host for other native shells.

The scene is `crates/sash/fixtures/interactive-counter.gscene`. Its edit states `copy: allow` and `paste: deny`. `crates/sash/src/interactive.rs` says emission of this profile is not a Windows launch and that `runtime_qualification` stays BLOCKED.

| Behaviour | Windows (Sash) | Linux (Wayland host) |
|---|---|---|
| Activation (Enter / button) | `crates/sash/src/interactive_keys.rs` maps `WM_KEYDOWN` plus `VK_RETURN` to `KeyAction::Activate` and leaves every other key as `Dispatch`. The generated pump in `crates/sash/src/interactive.rs` sends `BM_CLICK` to the button. The button is created as `BS_DEFPUSHBUTTON`. `WM_COMMAND` activates only when the control id is that button and the notification is 0. The controls disposition says Enter activates it. Admitted in generated Win32 code, not launched. | `crates/goya-wayland/src/lib.rs` keeps Enter (evdev 28) as `PlatformEvent::KeyChar('\n')`. `KeySpecial` does not contain Enter. The left pointer button `0x110` emits `PointerPress` or `PointerRelease` at the last surface position and does not name a button. Present in the Wayland host for other shells, not bound to the interactive counter scene. The host does not activate this scene's button. |
| Tab focus | `crates/sash/src/interactive_keys.rs` maps Tab to `FocusNext` and Shift-Tab to `FocusPrev`. The generated pump in `crates/sash/src/interactive.rs` calls `SetFocus` and cycles only the edit and the button. Both have `WS_TABSTOP`; the static heading and result do not. Initial focus is the edit. The controls disposition says Tab and Shift-Tab move between the edit and the button. Admitted in generated Win32 code, not launched. | `crates/goya-wayland/src/lib.rs` maps evdev 15 to `KeySpecial::Tab`, or to `KeySpecialWithModifiers` when Shift or Ctrl is down. The host does not move focus between an edit and a button. Present in the Wayland host for other shells, not bound to the interactive counter scene. The host does not apply the Sash edit/button focus cycle to this scene. |
| Space | `crates/sash/src/interactive_keys.rs` does not treat Space as an activation chord. `key_action` returns `Dispatch` for it, and the comment says the focused control receives it and the button's own handler activates on Space. The controls disposition in `crates/sash/src/interactive.rs` says Space activates the button only while that button has focus. Admitted in generated Win32 code, not launched. | `crates/goya-wayland/src/lib.rs` can emit Space as `PlatformEvent::KeyChar` (keymap-free evdev 57 is `' '`; with a keymap, a non-Ctrl space is the keymap character). It is not `KeySpecial` and it does not activate a button. Present in the Wayland host for other shells, not bound to the interactive counter scene. The host does not activate this scene's button on Space. |
| Copy/paste policy | `crates/sash/src/interactive_clipboard.rs` decides denial and does not read the clipboard. `clipboard_blocked` drops copy when copy is denied, paste when paste is denied, and cut only when cut is `CUT_DENY`. It recognises `WM_COPY`, `WM_PASTE`, `WM_CUT`, the control characters `0x03`, `0x16`, and `0x18`, and the Ctrl+C, Ctrl+Insert, Ctrl+V, Shift+Insert, Ctrl+X, and Shift+Delete chords. Delete without Shift is not a cut. `crates/sash/src/interactive.rs` uses profile `sash.win32.interactive/0.0.2` when the edit states copy and paste, subclasses that edit, and returns 0 before the text changes for a denied operation. The counter states copy allow and paste deny and does not state cut, so cut stays `CUT_DEFAULT` and the system cut command remains. With no gestures, profile `0.0.1` lets copy, cut, and paste reach the system edit. Admitted in generated Win32 code, not launched. | `crates/goya-wayland/src/lib.rs` emits `Shortcut::Copy` and `Shortcut::Paste` for Ctrl+C and Ctrl+V only on the xkb state path. The keymap-free fallback tracks no Ctrl modifier and emits no shortcuts. `set_clipboard_text` serves an in-memory `text/plain` selection; `request_clipboard_text` completes as `ClipboardText`. Neither call applies the scene allow/deny policy. Present in the Wayland host for other shells, not bound to the interactive counter scene. The counter's copy-allow and paste-deny policy is not applied by this host. |
| Window close | On `WM_DESTROY`, the generated procedure in `crates/sash/src/interactive.rs` releases the font, removes semantic ids, restores the edit subclass, and posts quit. `crates/sash/src/interactive_keys.rs` `shutdown_plan` destroys the window only when the pump failed and the window is still live, then the generated runner unregisters the class. The runtime disposition states that close sequence and says emission is not a Windows launch. Admitted in generated Win32 code, not launched. | `crates/goya-wayland/src/lib.rs` sets `close_requested` and pushes `PlatformEvent::CloseRequested` for an `xdg_toplevel` close and for `WindowAction::Close`. `request_close` destroys the toplevel. The host does not release a Sash font, semantic ids, or a window class. Present in the Wayland host for other shells, not bound to the interactive counter scene. That Sash close sequence is absent from the counter scene. |
| Resize | `WM_SIZE` in the generated procedure in `crates/sash/src/interactive.rs` calls `place_all`. Each control stays at its authored DIP origin, scaled by the window DPI, and its width and height are clipped to the client rectangle (or set to zero when the origin falls outside). Positions are not reflowed. The extent disposition says resizing clips controls and does not reflow them. Admitted in generated Win32 code, not launched. | `crates/goya-wayland/src/lib.rs` handles an `xdg_toplevel` configure with a positive changed width or height by storing that size, dropping the shared-memory buffers, and emitting `PlatformEvent::Resized`. `present_rgba` rejects a frame whose dimensions differ from the configured surface instead of scaling it. Present in the Wayland host for other shells, not bound to the interactive counter scene. Clipping the counter's controls without reflow is absent from the counter scene. |
| Text input / IME | The generated program in `crates/sash/src/interactive.rs` creates a system `EDIT` with `ES_AUTOHSCROLL`, subclasses it for the clipboard gate, focuses it at startup, and reads it with `GetWindowTextW`. Activation rejects a unit above `0x7F`. The program does not call an IME API and does not handle `WM_IME`. The edit control is admitted in generated Win32 code, not launched. IME handling is absent from the counter scene. | `crates/goya-wayland/src/lib.rs` binds `zwp_text_input_v3` when the global exists. `set_text_input_active` is disabled by default and enables or disables input around editable focus. After protocol `done`, the host emits `Preedit`, `PreeditWithCursor`, `DeleteSurroundingText`, and whole `CommitText`. Commit text is never synthesized into `KeyChar`. Keyboard text still uses the xkb keymap and compose path. Present in the Wayland host for other shells, not bound to the interactive counter scene. |

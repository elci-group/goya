# Wilder finding review

Review date: 2026-11-15. Wilder 0.3.0 analyzed the dirty working tree based on
`38c2f6132ef532e5b9b58b6a017e1f03cc1b3f5a`. Its 13.6% coverage and exit code 2
mean the report is incomplete; this review is not a security or release audit.
Windows readiness is temporarily deferred in the CI `uni` invocation. For
the equivalent local snapshot, run `uni --skip edwardian --fail-under 80 .`.
A plain `uni` command still includes Edwardian; restore it to CI when Windows
becomes a release target.

## Change hotspots

Wilder reported 17 medium-severity Git history hotspots over its latest 200
commits. These identify repeated changes, not established defects. `VERSION`
changed in all 200 commits because versioning updates it; it is not a source
module requiring decomposition. The other hotspots cluster in the canonical
Goya frontend and SDK, Neptune and Sash. They remain review priorities when
those areas change.

As a cross-check, `fract --format json index` rated the highest-churn production
files `neptune/src/main.rs` (0.806), `goya-lang/src/parser.rs` (0.754),
`sash/src/admit.rs` (0.735), `neptune/src/service.rs` (0.715),
`goya-sdk/src/lib.rs` (0.709), `neptune/src/transition_swift.rs` (0.687), and
`sash/src/emit.rs` (0.667) as warnings; none was its critical module. Fract's
fan-in numbers were zero for these files, so they do not establish dependency
centrality. Do not interpret the numerical scores as proof of correctness.

`cargo test --offline -p neptune -p sash -p goya-lang -p goya-sdk` passed in
this working tree. Kotlin execution is skipped where Java/Kotlin are absent;
Apple and Windows platform qualification remain separate. No historical churn
finding is claimed resolved by these tests.

## Large files

* `swiftly-x86_64.tar.gz` is a tracked 29,503,856-byte archive added in commit
  `184a76d`. It contains `swiftly` and `LICENSE.txt`; no repository source
  reference was found. Its SHA-256 is
  `0b26b568811404374c7d7f07276b6aad4145db5d1893a45f307de6a94ca8d9c3`.
  It is the Swiftly 1.2.0 installer published by Swift.org. The pinned,
  verified replacement is documented in [Swift bootstrap](swift-bootstrap.md).
  Removing it from the current tree does not remove bytes from Git history.
* `.uni/snapshot-v1.json` is generated by `uni` and ignored by Git. Wilder
  nevertheless includes it in its size scan. Removing the snapshot does not
  eliminate the cause: the next `uni` run recreates it.

## Analyzer limitations

Wilder reported Cargo metadata unavailable because it classified the sibling
workspace dependency `../goya-lang` in `crates/goya-ecosystem/Cargo.toml` as
external-looking. The path resolves inside this checkout; this is an analyzer
limitation, not evidence of an external dependency. Wilder 0.3.0 reports most
other domains as unimplemented or unavailable, including its security and
specialist adapters. Do not treat those domains as passing or infer that the
13.6% coverage is fixed by changing repository policy.

# Android clipboard transport (experimental)

This standalone Android library provides synchronous, explicitly invoked clipboard reads and writes. It is not wired into a Goya editor or any native command route. Access defaults to denial; the host must supply a fresh policy decision for every user-initiated operation, on the main thread. Policy exceptions deny access. Do not use reads as availability probes or poll the clipboard.

Writes accept only copy or cut and place bounded Unicode text on Android's clipboard. Reads accept only one direct `String` item with exactly `text/plain` metadata and reject HTML, URI, intent, styled text, malformed UTF-16 and text over the provisional 1 MiB UTF-8 limit. Reads normalize CRLF and CR to LF. No payloads are logged. Android can deny reads depending on focus and platform restrictions; failures return a generic status. Android may allocate or marshal clipboard data before this code can inspect its size, so this does not bound OS-side allocation.

The host must validate replacements, enforce protected-control and other policy masks, manage lifecycle/focus/revision reservations, and commit to the editor. For cut, it must reserve and validate first, export before removal, then revalidate and commit; on failed revalidation it must retain text and report the partial export. A successful write is only the observable return of Android's API, not proof of delivery or a durable clipboard. The transport does not guard other menu, IME, accessibility, or framework routes and must not be used to claim control or platform qualification.

With JDK 17+ and Android SDK 35 installed, run `../gradle/gradlew -p . check` in this directory. JVM tests cover the text validator; device tests, route enforcement, policy integration and lifecycle/race tests remain necessary.

# open-i — CLI fork of iloader

## Context
iloader (nab138/iloader, MIT) is a Tauri GUI sideloader. Its real work lives in `iloader_lib` (rlib) on top of non-Tauri crates (`idevice`, `isideload`, `keyring`); the Tauri layer is only state plumbing (`tauri::State`, `Window` event emission) plus interactive callbacks. The goal is a fork at **/home/sal/open-i** named **open-i** with the GUI replaced by a form3-formatted CLI, which later becomes neptune's manual-testing sideload mechanism.

## Phase 1 — Fork and de-Tauri the lib
1. `git clone https://github.com/nab138/iloader /home/sal/open-i`; create branch `open-i/main`; remove upstream branding per LICENSE-BRANDING (new name/icon in `tauri.conf`→deleted anyway, app string `"iloader"` → `"open-i"`, drop `count_downloads.ts`, website links in README).
2. In `src-tauri/src` (rename crate to `open-i-lib`, drop `staticlib`/`cdylib`):
   - Remove `tauri`, `tauri-plugin-*` deps from `Cargo.toml`; add `clap`, `form3` (path dep `/home/sal/3form`), keep `keyring` (linux-native-sync-persistent — already encrypted/persistent credentials, satisfying the persistent-encrypted-login requirement), `idevice`, `isideload`, `tokio`, etc.
   - `operation.rs`: replace `Operation::new(id, &window)` (Tauri event emission) with a `ProgressSink` trait (`start/complete/move_on/fail`); impls: `TermSink` (form3 spinners/status lines) and `JsonSink` (`--json`).
   - `account.rs`: replace `State<'_, SideloaderMutex>` params with plain `&SideloaderMutex`; replace the 2FA and max-certs window-event closures with injectable async callbacks (`Box<dyn AsyncFn>`-style, like the existing `MaxCertsCallbackBox`) that the CLI backs with terminal prompts (and a spinner while waiting). Keep keyring + `data.json` ids-list storage as-is (store plugin replaced by a tiny serde_json file helper — same `data.json` format).
   - `device.rs` / `pairing.rs` / `secure_storage.rs`: same `State<...>` → `&Arc<Mutex<...>>` mechanical refactor.
   - `lib.rs`: delete `run()` and Tauri builder; expose the plain async operations API.

## Phase 2 — CLI binary (`src-tauri/src/bin/` or new `[[bin]] open-i`)
Clap-based, form3 TUI style (banner, rounded tables, spinners), global `--json` for the form3 agent API:
- `login` (prompt email/password/anisette server, `--save` default-on → keyring; `--use <email>` = login_stored), `logout`, `whoami`
- `devices` — **device table printed after every command's output** (connected devices via usbmuxd)
- `device` / `device select` — compact interactive TUI picker (form3 table + key selection)
- `certs list`, `certs revoke <id>`, `app-ids list`, `app-ids delete <id>`
- `sideload <ipa>` — the showpiece: form3 animation (stage spinners install/download/pairing mirroring `Operation` stages, progress display, per-stage success/failure coloring, summary table with device + result)
- `sidestore install [--nightly] [--live-container]`
- `pairing place|export|apps|reset`
Exit codes: 0 ok, 1 operation failure, 2 usage.

## Phase 3 — Wire into neptune
Add `neptune sideload <file-or-ipa> [--format json]` in `crates/neptune/src/main.rs` (+ `sideload.rs` module) that locates `open-i` on PATH, runs `open-i sideload`, and maps outcomes to neptune's conventions (`--format json` machine report; status `BLOCKED` + exit 3 when open-i, keyring, or a connected device is unavailable; failure → exit 1). Manual-device-admission stays unclaimed, matching neptune's existing report style. Add tests using the existing command-test conventions in `crates/neptune/tests/` (mock PATH binary for deterministic outcomes).

## Verification
- `cargo build -p open-i*` compiles without tauri.
- `open-i devices`, `whoami`, `certs list` run headless (no device: clean error, exit 1; table printing verified).
- `--json` output parses.
- `cargo test -p neptune` green including new sideload tests.
- Full sideload requires hardware + Apple ID — leave as documented manual step.

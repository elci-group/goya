# Extend open-i beyond iloader: Team Selection, Certificate Creation, App ID Creation

## Context
open-i (fork of iloader) currently matches upstream's feature surface: login, device management, sideloading, cert list/revoke, app ID list/delete. But iloader itself has TODOs for team selection, certificate creation, and app ID creation. The underlying `isideload` crate already exposes these APIs — we just need to wire them into open-i's lib and CLI.

## Implementation Plan

### 1. Lib additions (`/home/sal/open-i/open-i/src/account.rs`)
Add public async functions using the existing `SideloaderGuard` pattern (which gives access to `Sideloader` → `DeveloperSession`):

**Team Selection:**
- `pub async fn list_teams(sideloader_state: &SideloaderMutex) -> Result<Vec<TeamInfo>, AppError>` — returns simplified `TeamInfo { name, team_id, type, status }`
- `pub async fn select_team(sideloader_state: &SideloaderMutex, team_id: String) -> Result<(), AppError>` — stores selected team_id in `data.json` store
- `pub async fn current_team(sideloader_state: &SideloaderMutex) -> Result<Option<TeamInfo>, AppError>` — returns selected team or first available

**Certificate Creation:**
- `pub async fn create_certificate(sideloader_state: &SideloaderMutex, name: String, csr_pem: String, device_type: Option<String>) -> Result<CertificateInfo, AppError>` — generates CSR or accepts user-provided CSR, submits via `submit_development_csr`, returns created cert info

**App ID Creation:**
- `pub async fn create_app_id(sideloader_state: &SideloaderMutex, name: String, identifier: String, device_type: Option<String>) -> Result<AppIdInfo, AppError>` — calls `add_app_id`, returns created `AppIdInfo`

**Key types to add (already defined in isideload, we re-export/convert):**
- `TeamInfo` — simplified from `DeveloperTeam`
- `CertificateInfo` — already exists, extend with `cert_content` for created certs
- `AppIdInfo` — from `AppId` struct

### 2. Store extension (`account.rs`)
Add `selected_team_id: Option<String>` to `StoreData` (already has `ids`, `current`, `anisette`, `selected_udid`).

### 3. CLI commands (`/home/sal/open-i/open-i/src/cli.rs`)
Add to `CertCommand`, `AppIdsCommand`, and new `TeamCommand`:

```
open-i team list [--format json]
open-i team select <team_id>
open-i team current

open-i certs create --name <name> [--csr <pem-file>] [--device-type <ios|mac>]
open-i certs list

open-i app-ids create --name <name> --identifier <bundle-id> [--device-type <ios|mac>]
open-i app-ids list
```

Interactive prompts for missing required args (like `team select` without arg → picker from `list_teams`).

### 4. Error handling
Reuse `AppError` variants. New operations use existing `SideloaderGuard::take()` pattern.

### 5. Tests
Add to existing neptune CLI tests using mock open-i, or standalone open-i tests with `NEPTUNE_OPEN_I_BIN` override pattern.
